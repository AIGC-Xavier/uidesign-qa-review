# UIdesign-qa-review

**AIGC-Xavier · UI 设计走查技能**

对照设计稿检查开发页面、截图或前端源码，将视觉还原偏差整理成有证据、可定位、便于开发修复的问题清单。

关注布局、尺寸、间距、圆角、字体、颜色和状态表现，忽略文案措辞、真实数据及图片主题的差异。

## 三种使用方式

| 输入材料 | 检查方式 | 交付重点 |
| --- | --- | --- |
| 设计稿＋实现截图 | 在相同尺度和状态下进行视觉对照 | 差异位置、截图证据和修正方向 |
| 设计稿＋页面链接 | 访问页面并采集对应状态，再与设计比对 | 页面与状态覆盖、视觉问题、无法检查的项目 |
| 设计稿＋前端源码 | 定位组件与样式来源，对照设计属性；能够运行时核验实际画面 | 文件与行号、组件或变量、偏差原因和修复位置 |

三种方式可以组合使用，适合设计验收、前端开发自查，以及修复后的回归检查。

## 核心能力

- **视觉还原检查**：检查容器布局、控件尺寸、字体层级、颜色、边框、圆角、阴影与图标样式。
- **源码定位**：将设计区域对应到页面组件、样式文件和设计变量，定位真正生效的代码。
- **样式追踪**：检查继承、优先级、组件变体、主题覆盖、断点及条件分支，避免只看某条样式声明就下结论。
- **多状态对照**：按需覆盖浅深色、焦点、悬停、禁用、加载、异常及浮层状态。
- **证据分级**：区分浏览器渲染确认、源码静态确认与待验证项，不把未运行的代码审查当作完整视觉验收。
- **开发交付**：提供影响程度、设计与实现差异、代码位置及修正方向；相同原因的问题合并记录。

## 走查维度

| 维度 | 具体检查内容 |
| --- | --- |
| 布局与对齐 | 页面结构、容器宽度与栏宽比例、水平和垂直对齐、并列项目的分布 |
| 尺寸与间距 | 控件宽高、横纵间隔、内容区边距，以及卡片和列表项的内边距 |
| 字体与排版 | 分别检查标题、正文、辅助文字的字体、字号、字重、行高和对齐方式 |
| 色彩与填充 | 页面及组件背景、各层级文字、图标、分割线、边框、按钮和标签填充色 |
| 圆角与形态 | 卡片、按钮、输入框、图片容器的边角，以及圆角与组件尺寸的关系 |
| 叠放与效果 | 元素前后关系、阴影、投影、背景模糊及遮罩表现 |
| 图标规格 | 图标尺寸、实际占用范围、线条粗细、颜色及与文字的对齐 |

检查需在对应的主题和状态下进行。文案和图片主题差异不作为还原问题，图片容器的比例、裁切和布局仍在检查范围内。

## 工作流程

1. **确定基准**：确认设计版本、目标页面、视口、主题与检查状态。
2. **取得材料**：读取设计和实现截图；提供源码时定位路由、组件及依赖的样式。
3. **逐层比对**：先检查页面结构，再检查组件几何、文字、色彩与状态表现。
4. **核验原因**：追踪适用样式；具备运行条件时，用浏览器截图和计算样式确认最终效果。
5. **整理报告**：按影响排序，提供证据和代码定位，列明阻塞与未覆盖范围。
6. **修复复查**：沿用问题编号，记录已修正、仍存在或无法复测的结果。

## 安装

下载本仓库，将包含 `SKILL.md` 的文件夹放到技能目录。Codex 默认路径为：

```text
~/.codex/skills/UIdesign-qa-review/SKILL.md
```

如果设置了 `CODEX_HOME`，使用该目录下的 `skills/UIdesign-qa-review`。已有同名技能时先比较内容，避免覆盖本地修改。

本项目保留 `UIdesign-qa-review` 的名称和大小写。若所用工具要求全小写标识，请同步调整目录名和 `SKILL.md` 中的 `name`。

## 使用示例

### 截图对照

```text
使用 $UIdesign-qa-review 对比这两张截图。
第一张是设计稿，第二张是开发页面。忽略文案和图片内容差异，
检查颜色、字号、间距、圆角与布局，输出开发可执行的问题清单。
```

### 页面与多状态走查

```text
使用 $UIdesign-qa-review 检查这个测试页面与 Figma 设计。
对齐视口与主题，覆盖默认、已输入、加载、错误及浮层状态。
记录无法触发的状态，并输出带内嵌证据图、可直接转发的 PDF 报告。
```

### 前端源码与设计稿比对

```text
使用 $UIdesign-qa-review 检查当前项目中指定页面或组件的源码，
与我提供的 Figma 设计稿进行比对。
定位实际使用的组件、样式、主题变量及响应式规则，
检查布局、按钮尺寸、输入框高度、字体、间距、圆角和状态样式。
能启动预览时再验证实际画面；不能运行的部分标明只做了静态检查。
每条问题给出文件与行号、设计依据、实现差异和具体修正方向。
本次先输出报告，不修改代码。
```

### 修复后复查

```text
使用 $UIdesign-qa-review 复查这批已修复问题。
对照原问题编号、设计稿和当前源码，检查相关页面及浅深色状态，
记录哪些已修正、哪些仍存在、哪些缺少测试条件。
```

## 报告内容

- **检查概况**：设计基准、实现版本、环境、检查方式及覆盖范围。
- **问题统计**：确认问题数量、影响程度分布；区分渲染确认与源码确认。
- **问题明细**：位置、状态、设计表现、实现表现、证据与修正建议。
- **代码定位**：提供源码时，附文件与行号、组件、选择器或变量及受影响范围。
- **待验证事项**：无法访问、无法运行、状态无法触发或证据不足的部分。

需要独立转发的 PDF 或 Word 报告时，要求把证据图片嵌入文件，避免转发后图片丢失。

## 特殊检查规则

- **同步核对设计规范**：提供设计规范或 Design Token 文档时，一并检查实现是否符合要求，并在问题中标明具体条目或变量。
- **谨慎判断拍照色差**：屏幕拍照可能受角度和光线影响，降低颜色判断精度；轻微差异需用直接截图或样式属性复核。
- **合并重复问题**：同一原因造成的多处偏差合并为一条“全局性问题”，列明已确认的影响范围，避免重复计数。
- **只列确认的偏差**：问题清单不罗列“检查通过”的维度；检查范围与待验证项分别说明。

## 工具与范围

这是供 AI 助手使用的工作指令，不附带浏览器、Figma 连接器、源码运行环境或文档生成器。页面访问、源码读取、预览启动和文档导出取决于所用工具与权限。

走查默认不修改代码和设计稿；用户要求修复时才执行对应修改。源码静态检查不能证明最终渲染效果，视觉报告也不能替代完整业务测试。仅有截图时，不把目测估计写成精确测量。
